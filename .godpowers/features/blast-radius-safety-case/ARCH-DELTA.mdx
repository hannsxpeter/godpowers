# Architecture Delta: Blast Radius Safety Case

## Scope

- [DECISION] This delta extends the existing Skill runtime, Stage 2 quality review, static impact helper, and executed-evidence ledger without adding a command, route, workflow, specialist type, dependency, service, or state authority.
- [DECISION] `references/building/BLAST-RADIUS.md` owns the shared review protocol, while `/god-review`, `/god-build`, `god-executor`, `god-quality-reviewer`, and the orchestrator runbook consume that source.
- [DECISION] `lib/impact.js` remains a static candidate generator and adds only backward-compatible metadata that labels its results as unproven with a maximum evidence level of 2.
- [DECISION] `lib/evidence.js`, `.godpowers/ledger/verifications.jsonl`, state rollups, and hash-chained gate events remain the only executed-proof path; an additive local resolver binds a record digest to its gate event and returns a sanitized reviewer projection.

## ADR-010: Bind Blast Radius Conclusions To Executed Evidence

- [DECISION] Context: the existing review flow can cite tests and affected files without naming the single condition that makes a change safe or proving that condition against the shipped code path.
- [DECISION] Decision: Stage 2 must produce one load-bearing safety fact, grade it on a five-level ladder, scan 10 boundary classes, and cite a fresh executed ledger record before it treats the fact as proven.
- [DECISION] Decision: evidence levels 1 through 3 remain `UNPROVEN`; level 4 requires a successful focused probe, and level 5 requires a successful applicable runtime or installed-boundary reproduction.
- [DECISION] Decision: high-impact `UNPROVEN` claims fail Stage 2, while lower-impact `UNPROVEN` claims warn and name one exact next proof.
- [DECISION] Decision: a change is wide when it crosses at least 3 boundary classes or at least 2 high-impact classes, and wide changes receive a second independent blast-radius pass in a fresh context inside Stage 2.
- [DECISION] Rationale: the existing ledger already records claim, command, substep, exit code, output tail, verification result, and timestamp, so a second store would create competing proof authority.
- [DECISION] Rationale: conditional independent review widens defect discovery for cross-boundary work without charging every bounded documentation or local refactor for another agent pass.
- [DECISION] Flip point: reconsider the wide-change threshold only after two release candidates record how often it triggers and whether the additional pass finds unique high-impact risks.
- [DECISION] Consequence: reviewer agreement cannot raise an evidence level, and static impact, grep, AST, LSP, import, or source-location results can only identify candidates for proof.

## Component Responsibilities

| Component | Responsibility |
|---|---|
| Shared blast-radius reference | [DECISION] Define the evidence ladder, boundary inventory, impact policy, proof procedure, output contract, and verdict rules. |
| `/god-review` | [DECISION] Detect whether Stage 2 is bounded or wide, spawn the required fresh-context pass or passes, and reconcile their evidence without treating consensus as proof. |
| `/god-build` | [DECISION] Apply the same Stage 2 safety-case gate before an atomic slice commit. |
| `god-executor` | [DECISION] Return a candidate safety fact, boundary classes, and focused proof command, without grading its own work or claiming that the candidate is settled. |
| `god-quality-reviewer` | [DECISION] Independently verify or replace the candidate fact, inspect every boundary class, match level 4 or 5 claims to fresh ledger evidence, and issue the final safety-case verdict. |
| `lib/impact.js` | [DECISION] Return affected-file and transitive-search candidates plus explicit unproven metadata; it never declares behavioral safety. |
| Existing evidence ledger | [DECISION] Retain the exact command-backed record used by level 4 and level 5 conclusions. |
| Evidence review resolver | [DECISION] Verify the ledger record against a hash-chained gate event, compare expected values locally, and return booleans plus bounded redacted metadata without raw output tails. |

## Critical Review Flow

1. [DECISION] The executor reads the approved slice, diff, relevant Pillars, and shared blast-radius protocol, then returns one candidate safety fact, the boundary classes it believes are implicated, and the smallest focused proof command.
2. [DECISION] Stage 1 verifies specification, acceptance, traceability, and scope without deciding the blast-radius safety case.
3. [DECISION] Stage 2 independently reads the diff and protocol, computes the 10-row boundary inventory, and verifies or replaces the executor's candidate fact.
4. [DECISION] Stage 2 counts crossed and high-impact classes; a bounded change receives one safety-case pass, while a wide change receives a second fresh-context pass.
5. [DECISION] Each pass checks dependency implementation, pinned version, local patches, lifecycle timing, public or serialized contracts, database or disk state, configuration or flags, generated or installed surfaces, package surfaces, and cross-language consumers.
6. [DECISION] A level 4 or 5 conclusion resolves through the local evidence-review helper to a successful fresh `godpowers verify` record with the same claim, exact command, canonical substep, reviewed-change window, matching digest-bound gate event, and valid event chain.
7. [DECISION] Stage 2 reconciles Confirmed Risks, Cleared Risks, and Unproven Claims; conflicting passes lower confidence or request proof and never average into a stronger evidence level.
8. [DECISION] Any confirmed blocking risk or high-impact `UNPROVEN` claim fails the slice, while a lower-impact `UNPROVEN` claim remains a visible warning with one exact next proof.

## Evidence And Failure Policy

| Level | Evidence | Review meaning |
|---|---|---|
| 1 | [DECISION] Reviewer assertion without a cited source. | [DECISION] `UNPROVEN`; it cannot clear any risk. |
| 2 | [DECISION] Specific source, dependency, schema, manifest, or `file:line` citation. | [DECISION] `UNPROVEN`; it can narrow the candidate surface only. |
| 3 | [DECISION] A traced failure path showing why a named bad case cannot reach the changed behavior. | [DECISION] `UNPROVEN`; the traced assumptions still need execution when the claim is load-bearing. |
| 4 | [DECISION] A focused successful probe executed through `godpowers verify`. | [DECISION] Proven for the exact code path and inputs exercised by the probe. |
| 5 | [DECISION] A successful runtime, installed-package, host, process, browser, service, or faithful consumer reproduction executed through `godpowers verify`. | [DECISION] Proven for the applicable delivery boundary exercised by the reproduction. |

- [DECISION] A failed, timed-out, attested-only, mismatched, or pre-change record cannot clear a risk.
- [DECISION] Runtime reproduction is required only when runtime, lifecycle, installation, package, process, service, browser, or host behavior can change the conclusion and an evidenced runnable target exists.
- [DECISION] A missing runnable target remains an Unproven Claim with owner, impact, and exact evidence needed; the reviewer does not invent a target or silently round level 4 up to level 5.
- [DECISION] Search output that finds nothing can clear the existence of a searched symbol within the stated scope, but it cannot prove runtime behavior or semantic compatibility.

## Trust And Privacy

- [DECISION] Focused probes inherit the existing shell boundary, timeout, output cap, and command-recording behavior from `lib/evidence.js`.
- [DECISION] Reviewers receive a sanitized local projection containing match booleans, bounded redacted metadata, record identity, and integrity verdict instead of raw command arguments or output tails.
- [DECISION] The safety-case protocol grants no new command-execution authority; it tells an already authorized reviewer how to bind a conclusion to existing verification evidence.
- [DECISION] Digest and chain checks detect accidental or inconsistent record mutation inside the trusted project workspace; they do not authenticate against an actor that can rewrite every trusted local file and recompute the complete chain.
- [DECISION] `god-quality-reviewer` remains independent from `god-executor`, and a wide-change second pass receives a fresh context rather than the first pass's conclusions.

## Capacity And Compatibility

- [DECISION] The boundary inventory has exactly 10 named classes, and a reviewer may mark a class not applicable only with an observed repository fact.
- [DECISION] The load-bearing safety fact and every high-impact Unproven Claim remain present even when other review details must be compacted.
- [DECISION] The protocol supports at least 500 changed files and 1,000 static candidates by summarizing candidates after the safety fact and blocking claims, not before them.
- [DECISION] The implementation preserves CommonJS, Node.js 18 or newer, the current two-stage public review contract, zero production dependencies, and the existing verification record shape.
- [DECISION] Test-only subprocess fixtures use fixed executable paths and arguments, a 10-second timeout, and a 1 MiB output cap so a hung fixture fails closed instead of stalling CI.

## No-Gos

- [DECISION] Do not add `/god-blast-radius`, another CLI operation, a route, a recipe, a workflow, a specialist type, or a hosted review service.
- [DECISION] Do not add a static-analysis dependency, model SDK, second evidence store, mutable review database, or new state writer.
- [DECISION] Do not expose raw verification output tails or unredacted command arguments to Stage 2 reviewer context when the local resolver can return the match and integrity verdict.
- [DECISION] Do not let an executor approve its own candidate safety fact or let two reviewers convert agreement into proof.
- [DECISION] Do not treat static impact output, source citations, or traced reasoning as level 4 evidence.
- [DECISION] Do not copy or lightly rewrite upstream pstack prose, code, fixtures, examples, or output formats.

## Architecture Have-Nots

- [x] [DECISION] Every component retains one responsibility and reuses the existing review and evidence owners.
- [x] [DECISION] The five evidence levels have distinct proof meanings and no lower-level aggregation shortcut.
- [x] [DECISION] The wide-change threshold is explicit, bounded, and reviewable after two release candidates.
- [x] [DECISION] High-impact uncertainty fails closed, while lower-impact uncertainty remains visible with one next proof.
- [x] [DECISION] Static candidates, executed proof, runtime proof, state authority, and reviewer independence remain separate contracts.
