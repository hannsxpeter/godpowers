## Program Design

### File Tree Delta

- [DECISION] Add four dependency-free runtime modules, five focused test files, one optional operations extension pack, and synchronized release evidence.

### Module Boundaries

- [DECISION] `verification-profile` owns form-specific user-path proof contracts, `debug-feedback-loop` owns pre-hypothesis repro validation, `why-evidence` owns multi-source confidence checks, and `invocation-policy` owns route execution policy.
- [DECISION] Existing event, route, program-design, specialist, extension, and release modules remain authoritative for their current surfaces.

### Public Contracts

- [DECISION] `/god-test-runtime` accepts all six product forms through one verification profile contract.
- [DECISION] `/god-archaeology --why <target>` produces cited confidence-calibrated evidence without treating null or contradictory results as success.
- [DECISION] `/god-trace --decisions` projects hash-chain-valid `decision.recorded` events.
- [DECISION] Every core route declares one invocation policy from the routing schema enum.

### Call And Data Flow

1. [DECISION] Skills select an existing route and call a narrow runtime validator before a specialist acts.
2. [DECISION] Validators return material checks; executed commands and hash-chained events remain the only verification evidence.
3. [DECISION] Optional triage and wizard work loads only after the operations pack is explicitly installed and invoked.

### Caller Usage

- [DECISION] Callers use one exported validator or projection per new module and receive stable plain-object results with `verdict`, checks, and findings where applicable.
- [DECISION] Skill contracts show the exact call and artifact path so a cold-context specialist does not reverse-engineer the helper.

### Interface Burden

- [DECISION] Each new module exposes at most the operations required by its direct skill callers; configuration for hypothetical providers, models, or trackers stays out of core.
- [DECISION] Route policy is one metadata string, and source-specific archaeology remains a bounded evidence-category record rather than a connector abstraction.

### Seam Justification

- [DECISION] Runtime validation is the test seam because skills and specialists are prose contracts while release gates need deterministic behavior.
- [DECISION] The operations pack is a real distribution seam because users may install or omit the issue-tracker and wizard workflows independently of core Godpowers.

### Alternative Shapes

- [DECISION] Alternative A, new core commands for verification, why, triage, and wizard, is rejected because it duplicates existing command families and increases always-loaded surface.
- [DECISION] Alternative B, prose-only specialist guidance, is rejected because release gates could not detect missing or contradictory contracts.
- [DECISION] Selected shape, subcommands plus narrow validators and one optional pack, keeps core routing stable while making the new behavior testable.

### Deviation Return Rule

- [DECISION] If implementation requires the same plan deviation twice, stop the active slice and return to planning before further production edits.

### Reused Patterns

- [DECISION] Reuse dependency-free CommonJS modules, plain-object validators, the existing test harness, route-quality sync, hash-chained events, and first-party extension manifests.

### Non-Goals

- [DECISION] Do not vendor upstream prose or code, hardcode a model family, introduce another orchestration mode, or auto-run external or destructive actions.
- [DECISION] Do not publish optional legacy packs or change root Node.js support.

### Verification Points

- [DECISION] Each slice starts with focused red tests and ends with its focused suite green.
- [DECISION] Closeout runs `npm test`, `npm run lint`, `npm run pack:check`, `npm run release:check`, exact package publish workflows, and isolated installed-package verification.
